# Arquitectura Portal de Selección de Hechos (Versión Refinada)

## 1. Usuarios y Roles

- **Roles definidos:**
    
    - Seleccionador → filtra y marca notas relevantes.
        
    - Escritor → redacta nuevas notas o enriquece existentes.
        
    - Editor → revisa y edita contenido.
        
    - Editor General → valida la selección y edición final.
        
    - Administrador → gestiona usuarios, permisos y configuración.
        
- **Control de acceso:**
    
    - Autenticación con JWT + OAuth2 (posible integración con Google/MS).
        
    - Autorización basada en roles (RBAC).
        

---

## 2. Frontend (Next.js + TailwindCSS)

- **Framework:** Next.js → SSR para rendimiento y SEO.
    
- **UI:** TailwindCSS (componentes reutilizables).
    
- **Funciones principales:**
    
    - Listado y búsqueda de noticias.
        
    - **Buscador avanzado** integrado con **ElasticSearch** (autocompletado, relevancia, filtros combinados).
        
    - Edición enriquecida y colaborativa en tiempo real:
        
        - Se recomienda **TipTap** (con Y.js como motor de colaboración).
            
            - Razón: TipTap tiene soporte nativo para **colaboración multiusuario** usando Y.js y ProseMirror, lo que lo hace ideal para texto enriquecido en entornos de edición periodística.
                
    - Reuniones integradas vía **Jitsi (iframe/API)**.
        
    - Descarga de documentos (Word/PDF) procesados en backend.
        

---

## 3. Backend (Python + FastAPI)

- **Framework:** FastAPI (asíncrono, rápido, soporta WebSockets).
    
- **Módulos principales:**
    
    1. **Ingesta de RSS**
        
        - Lectura con `feedparser`.
            
        - Normalización de datos y almacenamiento en BD.
            
        - Manejo de duplicados.
            
    2. **Buscador y Filtros**
        
        - Integración con **ElasticSearch**.
            
        - Indexación de notas (palabras clave, región, fecha, portal).
            
        - API REST/GraphQL para búsquedas rápidas.
            
    3. **Gestión de Notas**
        
        - CRUD de notas con estados (nueva, seleccionada, en edición, aprobada).
            
        - Edición colaborativa (WebSocket + Y.js).
            
    4. **Reuniones Online**
        
        - Integración con Jitsi (SDK/API REST).
            
        - Posible registro de reuniones y chat.
            
    5. **Exportación**
        
        - Generación de Word (`python-docx`) con estilo predefinido.
            
        - Exportación alternativa a PDF.
            
        - Opción de envío por correo (SendGrid/SMTP).
            
    6. **(Futuro) Machine Learning**
        
        - Clasificación automática de notas.
            
        - Análisis de relevancia / sentimiento.
            
        - Modelos de clustering o recomendación.
            

---

## 4. Base de Datos

- **Decisión: PostgreSQL**
    
    - Razones:
        
        - Escalabilidad para análisis de datos.
            
        - Soporte para JSONB (flexibilidad similar a MongoDB).
            
        - Compatible con Python (ORM: SQLAlchemy, Tortoise ORM).
            
        - Mejor integración futura con **ML pipelines** (Pandas, SQLAlchemy).
            
- **Redis** (opcional): cache para búsquedas rápidas y almacenamiento temporal de sesiones de edición colaborativa.
    

---

## 5. Infraestructura

- **VPS inicial (ej: DigitalOcean, Linode, AWS Lightsail).**
    
- **Docker Compose** para orquestar:
    
    - `frontend` (Next.js).
        
    - `backend` (FastAPI).
        
    - `db` (PostgresSQL).
        
    - `elastic` (ElasticSearch).
        
    - `redis` (opcional).
        
- **Escalabilidad futura:**
    
    - Migración a **Kubernetes**.
        
    - Procesos batch / ML jobs → ejecutados en contenedores separados o serverless (ej: AWS Lambda).
        

---

## 6. Integraciones Externas

- **Feeds RSS** → ingesta automática.
    
- **Jitsi** → reuniones online integradas.
    
- **SendGrid/SMTP** → envío de reportes o documentos por correo.
