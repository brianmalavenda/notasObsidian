**Proxmox Backup Server (PBS)** es una solución de respaldo de clase empresarial de código abierto diseñada específicamente para respaldar y restaurar máquinas virtuales, contenedores de [[Linux]] (LXC) e hosts físicos. Desarrollado en Rust para garantizar la máxima seguridad de memoria y un alto rendimiento de entrada/salida, PBS se integra de manera nativa y transparente con [[Proxmox_PVE]] Virtual Environment (PVE). Su objetivo principal es resolver las limitaciones de los respaldos tradicionales en entornos virtualizados, optimizando drásticamente el espacio de almacenamiento físico en disco y reduciendo el uso del ancho de banda de la red interna mediante algoritmos avanzados de gestión de datos.

El principio operativo de Proxmox Backup Server se basa en un modelo cliente-servidor que rompe con el concepto de respaldos "completos e incrementales" convencionales, implementando en su lugar una estrategia de **respaldo incremental permanente respaldado por deduplicación basada en bloques (chunks)**. Cuando se inicia un backup desde un nodo PVE, los datos se dividen dinámicamente en bloques de tamaño variable (normalmente con un promedio de 4 MB). Cada bloque se procesa mediante una función hash criptográfica SHA-256 que genera un identificador único (ID). El servidor PBS verifica si ese ID ya existe en su almacén de datos (_datastore_); si ya está guardado, solo indexa una referencia al bloque existente en lugar de duplicarlo. El resultado final de cada tarea de respaldo es simplemente un archivo de índice estructurado (`.fidx` o `.didx`) que mapea qué bloques componen la máquina en ese instante temporal exacto.

Para garantizar la integridad y la confidencialidad en entornos empresariales, la arquitectura de funcionamiento de PBS incluye cifrado del lado del cliente utilizando algoritmos de última generación como AES-256-GCM. Esto significa que los datos se cifran en el nodo de cómputo (PVE) antes de ser transmitidos a través de la red, asegurando que el servidor de backup nunca almacene datos legibles si no se posee la clave maestra. Además, implementa un sistema de verificación periódica de datos (_Data Verification_) que lee activamente los bloques almacenados para detectar de manera proactiva la degradación silenciosa de datos (_bit rot_) a nivel de hardware, asegurando que las restauraciones sean 100% viables cuando se requieran.

### Ventajas y Desventajas de Proxmox PBS

|**Ventajas**|**Desventajas**|
|---|---|
|**Deduplicación Inter-VM Ultraeficiente:** Al operar a nivel de bloques globales en todo el datastore, si diez máquinas virtuales comparten el mismo sistema operativo básico, los archivos del sistema solo se guardan una vez, reduciendo el almacenamiento requerido hasta en un 90%.|**Alta dependencia de almacenamiento rápido:** Debido a la naturaleza fragmentada de la deduplicación, las operaciones de lectura/escritura aleatorias son intensivas. Ejecutar PBS sobre arreglos mecánicos tradicionales (HDD) sin caché sólida degrada severamente el rendimiento; requiere idealmente SSDs/NVMe.|
|**Verificación y Restauración Granular:** Permite montar imágenes de discos de respaldo directamente desde la interfaz web para extraer o recuperar archivos específicos individuales (_Single File Restore_) en segundos, sin necesidad de restaurar la VM completa de varios terabytes.|**Falta de agentes nativos multiplataforma nativos:** Aunque sobresale en el ecosistema Proxmox PVE y Linux, carece de agentes de respaldo maduros y con interfaces gráficas integradas para entornos bare-metal heterogéneos, como servidores Windows nativos o bases de datos complejas fuera de VMs.|
|**Políticas de Retención e Inmutabilidad:** Soporta esquemas complejos de retención (GFS: _Grandfather-Father-Son_) automatizados y sincronización remota (_Remote Sync_) entre múltiples servidores PBS para arquitecturas de recuperación ante desastres (DRP), incluyendo soporte para esquemas de control de accesos basados en tokens (API Tokens).|**Cálculo de recursos en reconstrucciones:** En caso de fallas catastróficas del servidor de índices, la reconstrucción o verificación de datastores masivos basados en billones de bloques pequeños consume una cantidad significativa de memoria RAM y ciclos de CPU, impactando temporalmente las ventanas de backup.|
